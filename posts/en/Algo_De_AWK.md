# Why you should learn a bit of AWK

![AWK and linux get along fine](https://opensource.com/sites/default/files/lead-images/linux-penguin.png)


A while back I saw a person who, in a video, was manipulating the text of different files in a matter of seconds and it blew my head off. Immediately, I started searching like a possessed person what that magic was that person had done and how I could learn it.

To this day, 99% of the people I've talked to who work in the software world have never used it. Knowing a bit of AWK syntax, which can take you a few minutes (or even less if you use the gipiti chatbot) would drastically increase your ability to quickly manipulate the data of a text file. And on top of that, automated, avoiding human errors. Some of the most useful things I've gotten out of this little language, which aren't exactly "fundamentals", I'll be going through and maybe expanding on in the future.

AWK is a fun programming language. It's designed to process input strings. Once, in a live course I did at Telefónica (which I left halfway because it wasn't for me...) someone asked us to do an exercise to automatically generate receipt stubs or different kinds of billing for clients, and we could use any language we liked. For me it was pretty gratifying to do it in AWK, and on top of that the code turned out pretty short, to everyone's surprise. There were even people with python doing infinitely nested loops, when in AWK it took me a few lines with very simple logic.

To put some ordinary examples, let's suppose we have a small logs.txt file that looks like the text we have below.

```07.46.199.184 [28/Sep/2010:04:08:20] "GET /robots.txt HTTP/1.1" 200 0 "msnbot"```

```123.125.71.19 [28/Sep/2010:04:20:11] "GET / HTTP/1.1" 304 - "Baiduspider"```

These are just two records generated by apache, a bit simplified, so that google's spider or bing's bots don't go too crazy over my site...

AWK works like any other tool, grep for example, in the console. It reads from stdin and writes to stdout. It's easy to pipe things in and out of it. The command line syntax that concerns you is just the ```awk``` command followed by a string containing your program.

```
awk '{print $0}'
```

Most AWK programs start with a "{" and end with a "}". Everything in between the two braces runs once per line of the input file. Most AWK programs will print something. The program above will print a full line to the screen, and print appends a new line. $0 is the full line. So this program is an [identity operation](https://en.wikipedia.org/wiki/Identity_function), which copies the input to the output without changing it.

AWK parses the line automatically, using any whitespace as a delimiter, merging consecutive delimiters... And all of it is available in the variables $1, $2, $3, etc...


```
echo 'esto es una prueba' | awk '{print $3}' // prints 'una'
awk '{print $1}' logs.txt
```

```$ 07.46.199.184```

```$ 23.125.71.19```

Simple so far, no? And useful (I think). When I need to print the end of the string, the special variable NF contains the number of fields in the current line. I can print the last field by printing field $NF or I can manipulate the value to identify the field based on its last position. Or, if I want, I can print several things at once with the same ```print``` command.

```
echo 'esto es una prueba' | awk '{print $ NF}' // prints "prueba"
awk '{print $1, $(NF -2) }' logs.txt
```

```07.46.199.184 200```

```123.125.71.19 304```

Let's keep going... Maybe the subject is starting to sound familiar... but you can drop the things you're not interested in to print to the screen the ones we want to focus on. Another great variable is ```NR```, which we can use to format the output of the ```print``` command, leaving the comma out and with no spaces, since I'm not interested in them.

```awk '{print NR ") " $1 " -> " $(NF-2)}' logs.txt```

```1) 07.46.199.184 -> 200```

```2) 123.125.71.19 -> 304```

It's powerful... although you'll still be thinking it's a bit of nonsense. No? By the way, there's an extra function which is ```printf``` that works the way you expect, in case you prefer more formatting options. Now, not all files are separated by whitespace, or not all strings are. I'm looking at you, dates...

```
$ awk '{print $2}' lgos.txt
```

```[28/Sep/2010:04:08:20]```

```[28/Sep/2010:04:20:11]```

The date field is separated by "/" and ":". But I think I'm going to focus on doing piping rather than on learning AWK's syntax, because that way it makes more sense, and from there everyone can fend for themselves when it comes to finding new ways of doing things with AWK. What I'm going to do next is use a "pipe" from the previous command's output and feed it into another AWK with the command so it splits it from the colons. For that, the second program will have to have its own {}. I don't want to get into what that means either, just to show how things would be split.

```
$ awk '{print $2}' logs.txt | awk 'BEGIN{FS=":"}{print $1}'
```

```[28/Sep/2010```

```[28/Sep/2010```

I've simply specified that I wanted a different ```FS``` (field separator), and that I wanted to print the first field. Similar to how string handling would be done in other languages. And to get rid of the character, that [ that exists before the date?

```
$ awk '{print $2}' logs.txt | awk 'BEGIN{FS=":"}{print $1}' | sed 's/\[//'
```

```28/Sep/2010```

```28/Sep/2010```

We could keep splitting the string on the different "/" it contains and grab whichever object we want by accessing its position with the same trick, but I think that by this point, we get it. Now, let's learn some logic. If I only want to return the first 200 lines I could use ```grep``` but I'd end up with the ip address that contains 200, or a date from the year 2000. I could get the first field that has a 200 with AWK and then use grep, but then I'd lose the whole line, its context. AWK supports simple "if" statements. Like for example...

```
$ awk '{if ($(NF-2) == "200") {print $0}}' logs.txt
```

```07.46.199.184 [28/Sep/2010:04:08:20] "GET /robots.txt HTTP/1.1" 200 0 "msnbot"

There we have it. That way we could have every line that had a 200 in its "status". The if should be familiar by this point in the reading (because if not... you must be losing your mind) and I think it needs no explanation.

Let's finish now with a stupid example of how AWK code keeps a status across multiple lines. Let's suppose I want to add up all the status fields in the file (which can come in very handy to solve adventofcode or get you out of a jam at work). There are pretty obvious examples like this one, but one I use often is capturing the size of the generated files and of all the artifacts of a Machine Learning process and printing them to the logger. I can know the size of the generated files and the ram I'm going to need with just a single simple AWK command.

```
$ awk '{a+=$(NF-2); print "Total so far:", a}' logs.txt
```

```Total so far: 200```

```Total so far: 504```

I usually care more about the final value than the accumulation of them. And I can do it with commands known in the linux or programming world like ```tail -n1```, which will print the sum after the process has finished, using the END for that.

```
$ awk '{a+=$(NF-2)}END{print "Total:", a}' logs.txt
```

```Total: 504```

I think the power of AWK and when to use it has come across more or less clearly. For simple matters of text file manipulation, knowing said files, it's pretty useful and if you do it when you're with more people, the wow effect is guaranteed. The only catch is that sometimes it's a bit different from the usual way of programming, although it has many similarities to normal linux commands, and understanding the different types of code blocks and the positions, you can do really simple and fast things.

I hope it was useful, or at least that it was an entertaining read.
